InkJin — IRIS (Viva.com) QR Payment for Greek Artists
========================================================
Date: June 2026
Context: When the artist's bank/payout country is Greece (GR), offer clients TWO
         payment methods on the same checkout page:
           1. Stripe card (Visa / Mastercard / Amex) — existing flow, unchanged.
           2. IRIS via QR scan only — Greece instant bank payment; user scans QR
              with their banking app and pays. No IRIS redirect button or hosted
              checkout link on the InkJin page.
         Viva.com powers IRIS behind the QR (Smart Checkout URL encoded in QR).

Related files in repo today:
  - Artist country: user_details.payout_bank_country (e.g. 'GR')
  - Pricing: App\Services\BookingCheckoutPricingService
  - Stripe payments today:
      * Public tattoo booking  → InkJinController::createBookingPaymentIntent
      * Managed request        → UserController\RequestsController
      * Custom request         → UserController\CustomRequestsController
  - Artist payouts (Stripe): App\Services\ArtistPayoutService
  - Dev IRIS QR mock page:    /test/iris-payment (resources/views/iris/test-payment.blade.php)

1. EXECUTIVE SUMMARY
================================================================================

GOAL (CONFIRMED PRODUCT DECISION)
  For artists with payout_bank_country = 'GR', checkout offers BOTH:
    • Card — Stripe PaymentIntent (keep current card form + Confirm & Pay).
    • IRIS  — QR code only; customer scans with Greek banking app to pay.

  Non-Greek artists: Stripe card only (no change).

DUAL-CHECKOUT APPROACH
  Same page, two tabs (or side-by-side sections):

    [ Card ]  [ IRIS QR ]

  Card tab  → existing Stripe Elements flow (no Viva involvement).
  IRIS tab  → Viva payment order + QR canvas only (no "Open payment page" link).

  IRIS technical flow (QR encodes Viva URL with paymentMethod=29):
    1. User switches to IRIS tab → InkJin creates Viva order (POST /checkout/v2/orders).
    2. Backend builds Smart Checkout URL: ...?ref={orderCode}&paymentMethod=29
    3. Frontend renders QR from that URL (qrcode.js — same as /test/iris-payment).
    4. User scans QR with phone banking app → Viva IRIS → bank login → pay.
    5. Viva webhook → InkJin confirms booking (same outcome as Stripe confirm).

  Cards and IRIS are independent paths — user picks one; only one can complete
  the checkout. Cancel/expiry on IRIS does not affect Stripe tab.

WHY VIVA (not raw DIAS)
  - IRIS online is integrated into Viva Smart Checkout for Greek merchants.
  - Viva handles bank redirect, compliance, settlement, refunds.
  - QR on your page = QR encoding the Smart Checkout URL (Viva does not return a
    QR image; you generate it yourself — same as /test/iris-payment).

IMPORTANT CONSTRAINTS
  - IRIS via Viva is ASYNCHRONOUS: confirmation can take up to ~20 minutes.
    You MUST use webhooks; do not rely on redirect alone.
  - IRIS is NOT available in Viva demo/sandbox — production testing only.
  - IRIS is Greece-only: merchant in GR, customer paying from Greek bank apps.
  - No pre-auth / no recurring via IRIS today.
  - Settlement to merchant IBAN is next business day (statusId = F).

MARKETPLACE / ARTIST PAYOUTS
  InkJin today collects on the platform Stripe account and pays artists via
  Stripe Connect after the cancellation window. For Greek IRIS payments you need
  a parallel payout path:
    Option A (recommended long-term): Viva Marketplace API — onboard Greek artists
      as Viva connected accounts; split commission at payment time.
    Option B (MVP): Collect on InkJin's Viva platform account; pay Greek artists
      manually or via bank transfer until Marketplace is approved.
    Option C: Each Greek artist has their own Viva merchant account (heavy onboarding).

  Contact Viva sales for Marketplace / ISV access:
    https://www.viva.com/en-eu/product/marketplaces

3. VIVA SMART CHECKOUT + IRIS — TECHNICAL FLOW
================================================================================

STEP 0 — PREREQUISITES (BUSINESS / OPS)
  - InkJin platform (or per-artist) Viva merchant account registered in Greece.
  - OAuth 2.0 credentials: Client ID + Client Secret (Settings → API Access).
  - Payment source (sourceCode): 4-digit code for your website checkout.
  - Webhook URL registered in Viva (Settings → API Access → Webhooks).
  - Greek business IBAN registered with AADE for IRIS (artist responsibility if
    they are the merchant; platform responsibility if InkJin is merchant).
  - Docs:
      https://developer.viva.com/payment-methods/local-payment-methods/iris/
      https://developer.viva.com/smart-checkout/smart-checkout-integration/
      https://developer.viva.com/tutorials/payments/collect-payments-with-qr-code/

STEP 1 — OAUTH TOKEN
  POST https://accounts.vivapayments.com/connect/token
  (Production; use demo-accounts.vivapayments.com for non-IRIS testing)

  grant_type=client_credentials
  Authorization: Basic base64(client_id:client_secret)

  Response: { "access_token": "...", "expires_in": 3600 }
  Cache token in Laravel (Cache::remember) until expiry minus buffer.

STEP 2 — CREATE PAYMENT ORDER
  POST https://api.vivapayments.com/checkout/v2/orders
  Authorization: Bearer {access_token}
  Content-Type: application/json

  Body (amount is in CENTS — e.g. €50.00 = 5000):
  {
    "amount": 5000,
    "sourceCode": "1234",
    "customerTrns": "Deposit for tattoo booking — Artist Name",
    "merchantTrns": "inkjin:booking_request:42",
    "paymentTimeout": 1800,
    "customer": {
      "email": "client@example.com",
      "fullName": "Client Name",
      "phone": "6912345678",
      "countryCode": "GR",
      "requestLang": "el-GR"
    },
    "tags": ["inkjin", "managed_request", "artist:123"]
  }

  merchantTrns is YOUR idempotency / lookup key. Use a structured string:
    inkjin:{flow}:{model_id}
  Examples:
    inkjin:public_booking:pending_abc123
    inkjin:booking_request:55
    inkjin:custom_request:88

  Response: { "orderCode": 7271532565172601 }

  Store pending payment BEFORE showing QR:
    - viva_order_code
    - amount_cents
    - flow + reference ids
    - status = pending
    - expires_at (now + paymentTimeout)

STEP 3 — BUILD SMART CHECKOUT URL (IRIS PRE-SELECTED)
  Production:
    https://www.vivapayments.com/web/checkout?ref={orderCode}&paymentMethod=29

  paymentMethod=29 → IRIS (see Viva method ID table).

  Optional query params:
    &color=310f7a          (InkJin primary purple)
    &lang=el-GR            (Greek UI)

  IMPORTANT: Always append paymentMethod=29 for IRIS QR orders.
  Do NOT use paymentMethod=0 on the IRIS path — cards are handled by Stripe,
  not Viva. Each provider has its own payment session.

STEP 4 — DISPLAY QR ONLY ON INKJIN (NO REDIRECT / NO LINK)
  Viva does NOT return a QR image. Encode the IRIS-only Smart Checkout URL:

  Client-side (already used on /test/iris-payment):
    qrcode.js CDN → QRCode.toCanvas(canvas, checkoutUrl)

  Do NOT show on the IRIS tab:
    - "Open payment page" / "Continue to IRIS" button
    - Clickable checkout URL
    - iframe embedding Smart Checkout

  User must scan the QR with their banking app to pay.

  UI pattern (Greek artist — dual checkout):
    ┌──────────────────────────────────────────────────────────┐
    │  Secure Payment — €50.00 due now                         │
    │  [ Card ]  [ IRIS QR ]                                   │
    ├──────────────────────────────────────────────────────────┤
    │  CARD TAB (default):                                     │
    │    Card number / expiry / CVC / cardholder               │
    │    [ Confirm & Pay €50.00 ]  → Stripe PaymentIntent      │
    ├──────────────────────────────────────────────────────────┤
    │  IRIS QR TAB:                                            │
    │    Pay €50.00 — scan with your banking app               │
    │    ┌─────────────┐                                       │
    │    │             │                                       │
    │    │   QR CODE   │   Open your bank app → Scan to pay    │
    │    │             │                                       │
    │    └─────────────┘                                       │
    │    ⏳ Waiting for payment... (auto-refresh)              │
    │    QR expires in 30:00                                   │
    │    [ Regenerate QR ]  (if expired)                       │
    └──────────────────────────────────────────────────────────┘

  Mobile UX (QR-only constraint):
    - Best case: user on laptop/tablet, scans QR with phone (primary flow).
    - User on phone only: show full-width QR + short instruction:
        "Use another device to scan, or open your bank app's QR scanner
         and scan this screen."
      Do NOT add a redirect link — product decision is QR-only for IRIS.
    - Optional later: "Email me this QR" — still QR, not a pay link.

STEP 5 — CONFIRM PAYMENT (WEBHOOK — REQUIRED)
  IRIS is asynchronous. Redirect URLs alone are NOT sufficient.

  Register webhook event: Transaction Payment Created (EventTypeId 1796)
  URL: https://yourdomain.com/webhooks/viva/transaction-payment-created

  On POST:
    1. Respond HTTP 2xx quickly.
    2. Parse OrderCode, TransactionId, Amount, StatusId from payload.
    3. Call Retrieve Transaction API to verify (never trust webhook alone).
    4. Confirm StatusId = 'F' (Finished) and Amount matches pending record.
    5. Match merchantTrns / tags to your pending payment row.
    6. Idempotently create booking / mark request paid (same as Stripe confirm).
    7. Update pending payment status = completed.

  Also handle:
    - Order Updated (4865) — customer cancelled from Smart Checkout
    - Expired orders — mark pending as expired; let user start new payment

  Webhook verification (first-time setup):
    GET your endpoint → return JSON with Key from Viva "Retrieve webhook key" API.

STEP 6 — POLLING FALLBACK (UX)
  While webhook processes, poll from browser every 5s (max 5–10 min):
    GET /api/payments/viva/status?order_code=...

  Backend checks Retrieve Order / Retrieve Transaction or local DB status updated
  by webhook. When paid → redirect to bookings success page.

  This mirrors how you today wait for Stripe PaymentIntent status — but slower.

7. FRONTEND (DUAL TAB + QR ONLY + POLLING) — PSEUDOCODE
================================================================================

  // Tab switching — lazy create Viva order when IRIS tab first opened
  document.getElementById('tab-iris').addEventListener('click', () => {
    if (!irisOrderLoaded) startIrisQrPayment();
  });

  async function startIrisQrPayment() {
    const res = await fetch(vivaOrderUrl, { method: 'POST', headers: csrf });
    const data = await res.json();
    // QR only — encode checkout URL; do not expose as <a href>
    QRCode.toCanvas(document.getElementById('iris-qr'), data.checkout_url, {
      width: 260, margin: 2,
    });
    irisOrderLoaded = true;
    startExpiryCountdown(data.expires_at);
    pollVivaStatus(data.order_code);
  }

  // Card tab — unchanged Stripe flow
  document.getElementById('btnConfirmPay').addEventListener('click', async () => {
    const { client_secret } = await createStripePaymentIntent();
    await stripe.confirmCardPayment(client_secret, { payment_method: { card: cardElement } });
    await confirmBookingOnServer(paymentIntentId);
  });

  function pollVivaStatus(orderCode) {
    const interval = setInterval(async () => {
      const res = await fetch(statusUrl + '?order_code=' + orderCode);
      const data = await res.json();
      if (data.status === 'paid') {
        clearInterval(interval);
        window.location = data.redirect_url;
      }
      if (data.status === 'expired' || data.status === 'failed') {
        clearInterval(interval);
        showError('Payment expired. Please try again.');
      }
    }, 5000);
    setTimeout(() => clearInterval(interval), 600000); // 10 min max
  }
