InkJin — Viva.com IRIS QR Payment & Artist Payout — Implementation Guide
==========================================================================
Date: June 2026
Audience: Developers implementing Greek IRIS checkout + payout on InkJin

This document is the step-by-step build guide. For product context and Viva API
reference notes, also see: docs/iris-viva-qr-payment-greece.txt


================================================================================
1. WHAT WE ARE BUILDING
================================================================================

PRODUCT
  Greek artists (payout_bank_country = GR) get dual checkout on booking payment:

    [ Card ]     → Stripe PaymentIntent (existing — unchanged)
    [ IRIS QR ]  → Viva Smart Checkout URL encoded as QR; client scans with
                   Greek banking app (Piraeus, NBG, Alpha, Eurobank, etc.)

  Non-Greek artists: Stripe card only.

  IRIS tab rules (UX — already live):
    - QR only on page. No "Open payment page" link, no redirect button.
    - User picks ONE method. Card and IRIS are separate sessions.
    - IRIS confirmation is async (webhook + polling). Can take minutes.

PAYOUT (artist receives money)
  Today InkJin pays artists via Stripe Connect (ArtistPayoutService) after the
  cancellation window, using payment_intent_id on bookings.

  When client pays via IRIS:
    - Money lands in Viva (InkJin platform wallet OR artist connected account)
    - Artist payout must use a Viva path — NOT Stripe transfer

  Three payout models (pick one before Phase 4):

    MVP (fastest)
      InkJin Viva platform account collects all IRIS payments.
      After cancellation window → manual bank transfer OR batch payout to artist IBAN.
      Good for launch / smoke tests. Not scalable.

    Recommended (production)
      Viva Marketplace API — onboard each Greek artist as connected seller.
      Split commission at payment time (like Stripe Connect).
      ArtistPayoutService branches on payment_provider.

    Per-artist merchant (heavy)
      Each artist has own Viva merchant account + sourceCode.
      InkJin only facilitates QR creation. Artist manages settlement.
      Highest onboarding friction.

================================================================================
3. END-TO-END FLOW (TARGET ARCHITECTURE)
================================================================================

CLIENT PAYS WITH IRIS QR
------------------------

  1. Client opens IRIS tab (lazy — do NOT create Viva order until tab clicked)
  2. Frontend POST → /.../payment/viva/order
  3. Backend:
       a. Authorize user + validate booking/request can pay
       b. Compute amount via BookingCheckoutPricingService (same as Stripe)
       c. OAuth token from Viva (cached)
       d. POST /checkout/v2/orders → orderCode
       e. Insert pending_viva_payments row (status=pending)
       f. Return checkout_url + order_code + expires_at
  4. Frontend builds QR from checkout_url:
       https://www.vivapayments.com/web/checkout?ref={orderCode}&paymentMethod=29
       paymentMethod=29 = IRIS (Viva constant)
  5. Client scans QR → bank app → Viva IRIS → pays
  6. Viva webhook POST → InkJin verifies transaction → creates booking
  7. Frontend poll GET /.../payment/viva/status every 5s → redirect on paid

ARTIST GETS PAID (after cancellation window)
--------------------------------------------

  Stripe path (existing):
    Booking.payment_intent_id → ArtistPayoutService → Stripe Transfer

  Viva path (new):
    Booking.payment_provider = viva_iris
    Booking.viva_transaction_id stored at confirm time
    ArtistPayoutService::processBooking():
      if payment_provider === 'viva_iris':
        → VivaMarketplaceService::transferToSeller(...)   [Marketplace]
        OR mark for manual payout + admin tool            [MVP]

ASCII overview:

  Client                    InkJin                         Viva
    |                         |                              |
    |-- IRIS tab opened ----->|                              |
    |                         |-- OAuth token -------------->|
    |                         |-- Create order ------------>|
    |                         |<-- orderCode ----------------|
    |<-- checkout_url + QR ---|                              |
    |                                                         |
    |-- scan QR (phone bank app) ---------------------------->|
    |                         |<-- webhook (paid) -----------|
    |                         |-- verify transaction -------->|
    |                         |-- create Booking              |
    |<-- poll status=paid ----|                              |
    |                                                         |
    ... cancellation window passes ...
    |                         |-- payout artist (Viva) ----->|

4. VIVA ACCOUNT SETUP (OPS — DO FIRST)
================================================================================

Before writing code:

  1. Register InkJin (or Greek entity) as Viva merchant — Greece.
     https://www.viva.com/en-eu/signup

  2. Settings → API Access:
       - Client ID
       - Client Secret
       - Source Code (4-digit payment source for website)
       - Merchant ID

  3. Register webhook URL (production):
       POST https://yourdomain.com/webhooks/viva/transaction-payment-created
       Event: Transaction Payment Created (1796)
       Also: Order Updated (4865) for cancellations

  4. Webhook verification (Viva sends GET first):
       Return JSON with Key from "Retrieve webhook key" API.

  5. For Marketplace payouts — contact Viva sales:
       https://www.viva.com/en-eu/product/marketplaces
       IRIS + Marketplace requires production approval.

  6. Greek artists using IRIS must register professional IBAN with AADE:
       https://www.aade.gr/epaggelmatikos-logariasmos

IMPORTANT LIMITATIONS
  - IRIS is NOT available in Viva demo/sandbox. Test in production with small amounts.
  - IRIS is Greece-only (GR merchant, GR bank apps).
  - Confirmation can take up to ~20 minutes — webhooks are mandatory.
  - Settlement to IBAN: next business day (StatusId = F).

6. PHASE 1 — VivaPaymentsService (backend core)
================================================================================

Create: app/Services/VivaPaymentsService.php

Responsibilities:

  getAccessToken(): string
    POST {accounts_base}/connect/token
    grant_type=client_credentials
    Authorization: Basic base64(client_id:client_secret)
    Cache::remember('viva_access_token', token_cache_ttl, ...)

  createPaymentOrder(
      int $amountCents,
      string $merchantTrns,
      array $customer,      // email, fullName, phone, countryCode
      array $tags = []
  ): array
    POST {api_base}/checkout/v2/orders
    Body:
      {
        "amount": 5000,
        "sourceCode": "{source_code}",
        "customerTrns": "Deposit — {design title}",
        "merchantTrns": "inkjin:booking_request:55",
        "paymentTimeout": 1800,
        "customer": {
          "email": "...",
          "fullName": "...",
          "phone": "...",
          "countryCode": "GR",
          "requestLang": "el-GR"
        },
        "tags": ["inkjin", "managed_request", "artist:123"]
      }
    Returns: ['order_code' => ..., 'raw' => ...]

  buildIrisCheckoutUrl(int|string $orderCode): string
    return checkout_base
      . '/web/checkout?ref=' . $orderCode
      . '&paymentMethod=29'
      . '&color=310f7a'
      . '&lang=el-GR';

  retrieveTransaction(string $transactionId): array
    GET {api_base}/checkout/v2/transactions/{transactionId}

  retrieveOrder(int|string $orderCode): array
    GET {api_base}/checkout/v2/orders/{orderCode}

  isTransactionPaid(array $transaction): bool
    StatusId === 'F' (Finished) AND amount matches pending record

merchantTrns format (idempotency key — unique per checkout attempt):
  inkjin:public_booking:{session_or_user_id}:{tattoo_slug}
  inkjin:booking_request:{booking_request_id}
  inkjin:custom_request:{custom_request_id}

================================================================================

PUBLIC CALENDAR BOOKING (guest, session-verified email)

MANAGED REQUEST (logged-in)

CUSTOM REQUEST (logged-in)
  POST /user/custom-requests/{customRequest}/payment/viva/order

Controller pattern (example: RequestsController):

  public function createVivaOrder(Request $request, BookingRequest $bookingRequest)
  {
      $this->authorizeRequest($bookingRequest);
      if (!$bookingRequest->canPay()) return 422;
      if (!PaymentMethods::showIrisTab($artist)) return 422;

      $totals = $this->pricing->checkoutTotals($userDetail, $minPrice);
      $amountCents = (int) round($totals['total_due'] * 100);
      if ($amountCents < 30) return 422;  // confirm minimum with Viva

      // Reuse valid pending order if not expired
      $pending = PendingVivaPayment::query()
          ->where('booking_request_id', $bookingRequest->id)
          ->where('status', 'pending')
          ->where('expires_at', '>', now())
          ->first();

      if (!$pending) {
          $merchantTrns = "inkjin:booking_request:{$bookingRequest->id}:" . Str::uuid();
          $order = $this->viva->createPaymentOrder(...);
          $pending = PendingVivaPayment::create([...]);
      }

      return response()->json([
          'order_code'    => $pending->viva_order_code,
          'checkout_url'  => $this->viva->buildIrisCheckoutUrl($pending->viva_order_code),
          'amount_cents'  => $pending->amount_cents,
          'currency'      => 'eur',
          'expires_at'    => $pending->expires_at->toIso8601String(),
      ]);
  }

  public function vivaPaymentStatus(BookingRequest $bookingRequest, Request $request)
  {
      // Check pending row status (updated by webhook) OR call retrieveOrder as fallback
      return ['status' => 'pending|paid|expired|failed', 'redirect_url' => '...'];
  }

9. PHASE 4 — Webhook (required)
================================================================================

Route (no CSRF):
  Route::post('/webhooks/viva/transaction-payment-created', ...)
  Route::get('/webhooks/viva/transaction-payment-created', ...)  // verification

Create: app/Http/Controllers/Webhooks/VivaWebhookController.php

  GET  → return ['Key' => config('services.viva.webhook_key')]

  POST → handleTransactionPaymentCreated(Request $request):
    1. Log payload (redact PII in production logs)
    2. Extract OrderCode, TransactionId, Amount, StatusId
    3. Call VivaPaymentsService::retrieveTransaction($transactionId)
    4. Verify StatusId = 'F' and amount matches pending_viva_payments row
    5. DB::transaction + lockForUpdate on pending row
    6. If pending.status already paid → return 200 (idempotent)
    7. Route by flow → confirm booking:

         public_booking     → InkJinController logic / new BookingPaymentConfirmationService
         managed_request    → ManagedRequestBookingService::createBookingFromRequest(...)
         custom_request     → CustomRequestBookingService equivalent

    8. Set booking.payment_provider = 'viva_iris'
       booking.viva_order_code, viva_transaction_id
    9. pending.status = paid, paid_at = now()
    10. Return 200 quickly

Refactor recommendation:
  app/Services/BookingPaymentConfirmationService.php
    confirmFromStripePaymentIntent(PaymentIntent $intent, ...)
    confirmFromVivaPayment(PendingVivaPayment $pending, ...)
  Avoid duplicating booking creation in 3 controllers + webhook.

  var irisOrderLoaded = false;

  tabIris.addEventListener('click', function () {
    setActiveTab('iris');
    if (!irisOrderLoaded) startIrisQrPayment();
  });

  async function startIrisQrPayment() {
    var res = await fetch(vivaOrderUrl, {
      method: 'POST',
      headers: { 'Accept': 'application/json', 'Content-Type': 'application/json', 'X-CSRF-TOKEN': csrf },
      body: JSON.stringify({ /* flow-specific fields */ })
    });
    var data = await res.json();
    if (!res.ok) { showError(data.message); return; }

    QRCode.toCanvas(document.getElementById('irisQrCanvas'), data.checkout_url, {
      width: 260, margin: 2, color: { dark: '#310f7a' }
    });

    irisOrderLoaded = true;
    startExpiryCountdown(data.expires_at);
    pollVivaStatus(data.order_code);
  }

  function pollVivaStatus(orderCode) {
    var interval = setInterval(async function () {
      var res = await fetch(vivaStatusUrl + '?order_code=' + orderCode);
      var data = await res.json();
      if (data.status === 'paid') {
        clearInterval(interval);
        window.location.href = data.redirect_url;
      }
      if (data.status === 'expired' || data.status === 'failed') {
        clearInterval(interval);
        document.getElementById('irisQrRegenerate').classList.remove('hidden');
      }
    }, 5000);
    setTimeout(function () { clearInterval(interval); }, 600000);
  }
