Overview
Bookpay uses Viva Wallet as its payment processor. For Greek clients, IRIS must be offered at checkout — it is mandatory per Bookpay's payment rules. This document covers the complete end-to-end integration: authentication, payment order creation, checkout redirect, success/failure handling, and transaction verification.

IRIS is already enabled on your account
All Viva Wallet merchants in Greece have IRIS activated by default. No separate IRIS account or application is required. The only requirement is passing countryCode: GR in each payment order for Greek clients.

Integration Flow
The full payment flow has 5 steps. Steps 1, 2, and 5 run on your backend. Step 3 is a frontend redirect. Step 4 is handled by Viva.

Step	Where	What Happens
1. Get access token	Backend	Exchange Client ID + Secret for Bearer token
2. Create payment order	Backend	POST order to Viva API, receive orderCode
3. Redirect client	Frontend	Send client to Viva's hosted checkout page
4. Client pays	Viva (hosted)	Client selects IRIS, logs into bank, approves
5. Verify transaction	Backend	Confirm payment before marking booking as paid


Step 1 — Get Access Token
Use your Client ID and Client Secret to obtain a Bearer token. This is the only place these credentials are used. Cache the token and refresh it before it expires (TTL is typically 3600 seconds).

Endpoint
POST https://accounts.vivapayments.com/connect/token
Content-Type: application/x-www-form-urlencoded

Request Body
grant_type=client_credentials
&client_id=YOUR_CLIENT_ID
&client_secret=YOUR_CLIENT_SECRET

Response
{
  "access_token": "eyJhbGciOiJSUzI1NiIsInR...",
  "expires_in": 3600,
  "token_type": "Bearer"
}

Node.js Example
let cachedToken = null;
let tokenExpiry = 0;
 
async function getVivaToken() {
  if (cachedToken && Date.now() < tokenExpiry - 60000) {
    return cachedToken;
  }
  const res = await fetch('https://accounts.vivapayments.com/connect/token', {
    method: 'POST',
    headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
    body: new URLSearchParams({
      grant_type: 'client_credentials',
      client_id: process.env.VIVA_CLIENT_ID,
      client_secret: process.env.VIVA_CLIENT_SECRET,
    })
  });
  const data = await res.json();
  cachedToken = data.access_token;
  tokenExpiry = Date.now() + data.expires_in * 1000;
  return cachedToken;
}


Step 2 — Create Payment Order
Called from your backend when a client initiates a payment. Returns an orderCode which is used to redirect the client to checkout.

Endpoint
POST https://api.vivapayments.com/checkout/v2/orders
Authorization: Bearer {access_token}
Content-Type: application/json

Request Body
{
  "amount": 5000,
  "customerTrns": "Bookpay Booking #123",
  "customer": {
    "email": "client@example.com",
    "fullName": "John Smith",
    "countryCode": "GR",
    "phone": "+306912345678"
  },
  "paymentTimeout": 300,
  "preselectedPaymentMethod": "IRIS",
  "allowRecurring": false,
  "maxInstallments": 0,
  "sourceCode": "2461"
}

Key Parameters
Parameter	Value / Notes
amount	In cents. €50.00 = 5000
countryCode	GR for Greek clients — required for IRIS to appear
preselectedPaymentMethod	"IRIS" for GR clients, omit for UK clients
sourceCode	Always "2461"
paymentTimeout	Seconds before the order expires (300 = 5 min)

Response
{
  "orderCode": 176851274751,
  "statusId": "A"
}

Note: Detect GR clients from the E.164 phone prefix +30. If the client phone starts with +30, set countryCode: GR and preselectedPaymentMethod: IRIS. For UK (+44) clients, omit both or set countryCode: GB with no preselection.

Node.js Example
async function createPaymentOrder({ amountCents, email, fullName, phone, bookingRef }) {
  const token = await getVivaToken();
  const isGreek = phone.startsWith('+30');
 
  const body = {
    amount: amountCents,
    customerTrns: `Bookpay Booking #${bookingRef}`,
    customer: { email, fullName, phone, countryCode: isGreek ? 'GR' : 'GB' },
    paymentTimeout: 300,
    allowRecurring: false,
    maxInstallments: 0,
    sourceCode: process.env.VIVA_SOURCE_CODE,
    ...(isGreek && { preselectedPaymentMethod: 'IRIS' }),
  };
 
  const res = await fetch('https://api.vivapayments.com/checkout/v2/orders', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${token}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify(body),
  });
 
  const data = await res.json();
  return data.orderCode;
}


Step 3 — Redirect Client to Checkout
Once you have the orderCode, redirect the client's browser to the Viva hosted checkout page. Do not load this in an iframe — IRIS requires a full-page redirect and will not function inside an iframe.

Redirect URL
https://www.vivapayments.com/web/checkout?ref={orderCode}

What the client sees
If preselectedPaymentMethod is set	If not set
Client lands directly on IRIS screen	Client sees payment method selection
Client selects bank and logs in	Client chooses card, IRIS, etc.
Approves payment in their bank app	Continues through selected method

Note: Save the orderCode to your database before redirecting. You will need it to cross-reference after the client returns.


Step 4 — Handle the Return
After the client completes (or fails) the payment, Viva redirects them back to your configured URLs. Both URLs receive query parameters automatically appended by Viva.

Success URL
https://book.inkjin.com/viva/success
  ?s={orderCode}
  &t={transactionId}
  &lang={language}

Failure URL
https://book.inkjin.com/viva/fail
  ?s={orderCode}
  &t={transactionId}
  &lang={language}

Parameter reference
Param	Name in Viva config	Contains
s	Order Code	The orderCode from Step 2
t	Transaction ID	Viva's unique transaction identifier
lang	Language	Language used at checkout (e.g. el, en)

Important: Do not mark a booking as paid based on the redirect alone
The redirect URL can be manipulated. Always verify the transaction on your backend (Step 5) before updating booking status.


Step 5 — Verify the Transaction
When the client lands on your success page, your backend must immediately call Viva's API to verify the transaction. Only mark the booking as paid after this check passes.

Endpoint
GET https://api.vivapayments.com/checkout/v2/transactions/{transactionId}
Authorization: Bearer {access_token}

Key response fields to verify
Field	Expected Value	Notes
statusId	"F"	F = completed/captured
amount	Your order amount (cents)	Must match what you charged
orderCode	Your saved orderCode	Cross-reference with your DB

Node.js Example
async function verifyTransaction(transactionId, expectedAmount, expectedOrderCode) {
  const token = await getVivaToken();
 
  const res = await fetch(
    `https://api.vivapayments.com/checkout/v2/transactions/${transactionId}`,
    { headers: { 'Authorization': `Bearer ${token}` } }
  );
 
  const data = await res.json();
 
  if (
    data.statusId === 'F' &&
    data.amount === expectedAmount &&
    String(data.orderCode) === String(expectedOrderCode)
  ) {
    return { verified: true, transaction: data };
  }
 
  return { verified: false, transaction: data };
}
 
// In your /viva/success handler:
const { s: orderCode, t: transactionId } = req.query;
const order = await db.getOrderByCode(orderCode);
const result = await verifyTransaction(transactionId, order.amountCents, orderCode);
 
if (result.verified) {
  await db.markBookingPaid(order.bookingId, transactionId);
  res.redirect('/booking/confirmed');
} else {
  res.redirect('/booking/payment-error');
}


Bookpay Payment Rules
These rules must be implemented in the createPaymentOrder function:

Rule	Implementation
Charge in artist's currency	amount is always in the artist's local currency
GR client + GR artist → show IRIS	countryCode: GR + preselectedPaymentMethod: IRIS
UK client + UK artist → cards only	countryCode: GB, no preselectedPaymentMethod
Cross-border → universal methods	Omit preselectedPaymentMethod
Detect client country	Parse E.164 phone: +30 = GR, +44 = GB

IRIS is Asynchronous — Webhooks Required
Critical: IRIS payments are not instant
Unlike card payments, IRIS confirmation can take up to 20 minutes. Do not rely solely on the success redirect to mark a booking as paid. You must set up a webhook to receive the final payment confirmation.

How It Works
When a client pays with IRIS, the flow is:

Step	What happens
Client redirected to success URL	Viva redirects immediately after the client approves in their bank app
Payment status: pending	The booking should show as 'payment pending', not confirmed
Viva sends webhook (up to 20 min)	Viva POSTs a Transaction Payment Created event to your webhook URL
Backend receives webhook	Verify the payload, then mark booking as paid and confirm

Setting Up the Webhook
In your Viva dashboard: Menu → Settings → Webhooks → Add webhook URL.

Webhook event to subscribe to
Transaction Payment Created

Webhook payload (key fields)
{
  "EventTypeId": 1796,
  "EventTypeName": "Transaction Payment Created",
  "TransactionId": "...",
  "OrderCode": 176851274751,
  "StatusId": "F",
  "Amount": 5000,
  "PaymentMethodId": "IRIS",
  "MerchantId": "..."
}

Webhook handler (Node.js)
app.post('/webhooks/viva', async (req, res) => {
  const event = req.body;
 
  // Only process successful IRIS (and card) payments
  if (event.StatusId !== 'F') {
    return res.sendStatus(200); // Acknowledge but ignore
  }
 
  const { TransactionId, OrderCode, Amount } = event;
 
  // Find the booking by orderCode
  const order = await db.getOrderByCode(String(OrderCode));
  if (!order) return res.sendStatus(200);
 
  // Verify amount matches
  if (order.amountCents !== Amount) {
    console.error('Amount mismatch on webhook', { OrderCode, Amount });
    return res.sendStatus(200);
  }
 
  // Mark booking as paid
  await db.markBookingPaid(order.bookingId, TransactionId);
  await notifications.sendConfirmation(order.bookingId);
 
  res.sendStatus(200); // Always return 200 to acknowledge
});

Always return HTTP 200 to Viva
If your webhook endpoint returns anything other than 200, Viva will retry the delivery. Always acknowledge receipt with 200, even if you choose not to process the event.

Booking Status Flow for IRIS
Event	Booking Status	Show to client
Client redirected to success URL	payment_pending	"Payment received, confirming..."
Webhook received + verified	paid / confirmed	Booking confirmation + receipt
No webhook after 30 min	payment_timeout	Ask client to contact support
Failure URL hit	payment_failed	"Payment failed — please try again"
